Agent-first plan

Repo: g4rcez/writeme-editor · Date: 2026-11-23 · Linter: oxlint (minimal config) · Formatter: oxfmt · Package manager: npm (workspaces) · Read-only audit. No changes applied.

Summary

Trust level: MEDIUM. Types are strict and CI is strong (Playwright shards, merge gate, knip). But oxlint does not run on the main app code in CI, and CLAUDE.md points to a src/ directory that no longer exists.

Stack: Electron + React 19 + Tiptap + Vite, npm workspaces (packages/editor, cli, math, mcp, mobile, ios, android, landing). Tests: Vitest + Playwright. Also: knip, oxfmt, tsc with strict + noUncheckedIndexedAccess.

  1. Run oxlint on packages/*/src in CI. Today CI lints only tests, build and scripts (.github/workflows/test.yml:52).
  2. Fix CLAUDE.md. 27 lines reference src/…, which was moved to packages/editor/src/. Agents get wrong paths.
  3. Add one verify script (lint + typecheck + test) and ban the type escapes and effect/timer patches that the scans found.

Layer 1 - Constraints in code

1. Lint gate skips the app code

effort S
Evidence
CI runs oxlint --deny-warnings only on tests build playwright.*.config.ts scripts/… (.github/workflows/test.yml:52). No other workflow runs lint. npm run lint exists but is not in CI. (observed)
Why it hurts
An agent can add code to packages/editor/src that fails lint and still get a green PR. Rules are advisory. (inferred)
Fix
Run lint on the whole repo in CI. First run it locally and see the count. The config sets correctness and nursery to warn; warnings are ignored by agents. Set them to error after the backlog is fixed, or run with --deny-warnings once clean.
Error message
Lint failed. Cause: the rule found a real defect. Fix: change the code, not the rule. Do not add a disable comment. (CI step name or script echo; oxlint core rules cannot carry custom text.)

2. Minimal oxlint config. Adopt the nkzw baseline

effort Mneeds dependency change
Evidence
oxlint.config.ts has 7 plugins, 2 categories at warn, and 1 rule. No type-aware rules, no no-console, no no-explicit-any. (observed)
Why it hurts
Agents copy what exists. The scans show the patterns below already spread widely. (inferred)
Fix
Add @nkzw/oxlint-config (check the repo index.js for current rule names before adoption). Path: (1) extend preset, (2) set every newly failing rule to "off", commit green, (3) enable one rule at a time and fix, one commit each. Also set reportUnusedDisableDirectives: 'error' (only 1 disable comment exists today). Type-aware rules need oxlint 1.94+ and tsrs. Confirm which rules stay off with the maintainer.

3. Type escapes: any, non-null !, @ts-ignore

effort L (any) / S (ts-ignore)
Evidence
any: 343 matches (245 in non-test code). Top: main-process/database.ts (30), preload.ts (21), store/repositories/browser/notes.repository.ts (15). Non-null assertions: 220 (47 non-test). @ts-ignore / @ts-expect-error: 5, e.g. lib/migration-service.ts:97 (bare @ts-ignore), app/lib/open-directory-as-workspace.ts:27. (observed; regex scan, may include false positives)
Why it hurts
The IPC and DB boundary is where any concentrates. Agents will copy it into new IPC handlers. The type checker is then blind exactly where Electron bugs live. (inferred)
Fix
Enable typescript/no-explicit-any, typescript/ban-ts-comment (allow @ts-expect-error with description), typescript/no-non-null-assertion. Start with a ratchet: error for new files, off via overrides for the listed files. Type the IPC channel map in preload.ts first; most any follows from it.
Error message
`any` hides the real type. Cause: the value shape is not modeled. Fix: define the type (or use `unknown` and narrow). Do not cast or suppress. (needs no-restricted-syntax to carry custom text.)

4. useEffect outside wrappers (opt-in)

effort L
Evidence
282 calls. Top: app/editor.tsx (19), app/root-layout.tsx (13), app/elements/raw-markdown-editor.tsx (9). (observed)
Why it hurts
Effects need judgment on dependencies and cleanup. Agents add effects to sync state and create loops. (inferred)
Fix
Do not ban at once. Turn on react/exhaustive-deps, react/rules-of-hooks, and react/set-state-in-effect (if the installed oxlint has it) at error. Ban new useEffect only in new files via overrides, with an approved wrapper (for example useMountEffect / useSubscription). Team choice.
Error message
Direct useEffect is not allowed here. Cause: effects hide data flow. Fix: derive the value, use an event handler, or use the approved wrapper. Do not add an effect to sync state.

5. Imperative timers (opt-in)

effort M
Evidence
152 calls to setTimeout/setInterval/requestAnimationFrame (81 setTimeout/rAF in non-test code). Top: app/commander.tsx (11), app/extensions/search-replace.ts (4). A wrapper already exists: lib/animation-frame.ts. (observed)
Why it hurts
Timers are the usual patch for ordering bugs between Tiptap, React and Electron. Agents add setTimeout(…, 0) until the test passes. (inferred)
Fix
no-restricted-globals for setTimeout, requestAnimationFrame in app/. Allow only lib/animation-frame.ts and a named debounce helper. Existing hits go in an override list that must shrink.
Error message
Timer used to delay work. Cause: ordering or state model is wrong. Fix: fix the ordering, or use lib/animation-frame or the debounce helper. Do not patch with a timer.

6. Import boundaries: renderer vs main process, and ../ paths

effort M
Evidence
Renderer code imports main-side folders in 3 files: store/repositories/adapters/electron.adapter.ts, app/editor.tsx, app/commands/clipboard-listener.command.ts (some may be type-only; not verified). 50 files use from "../../…" although CLAUDE.md says never to. 57 files touch window.electronAPI. Layout has app/, main-process/, ipc/, server/ under one src/. (observed)
Why it hurts
A renderer file that imports Node code breaks the PWA or the sandbox at runtime, not at lint time. A prose rule about @/ is already ignored 50 times. (inferred)
Fix
(a) no-restricted-imports with pattern ["../*"] to enforce @/. (b) Boundary rule: app/**, store/**, lib/** may not import main-process/**, ipc/**, server/** (allow import type). Use oxlint overrides with no-restricted-imports, or add dependency-cruiser if you need a graph rule. (c) Optional: the 57 window.electronAPI call sites should go through one guarded module; ban direct window.electronAPI with no-restricted-syntax.
Error message
Renderer code imports main-process code. Cause: process boundary crossed. Fix: add a typed IPC channel in preload.ts and call it through the guarded electronAPI module. Do not import main-process modules here.

Layer 2 - Verification

One fast verify command

effort S
Evidence
Local scripts: lint, typecheck, test, knip, format:check are separate. CI runs typecheck and test in separate jobs, lint on a subset, and no knip or format:check was found in workflows. (observed)
Fix
Add one script. CI and agents call the same command. Run time not measured (skipped).
"verify": "npm run lint && npm run format:check && npm run typecheck && npm test",
"verify:full": "npm run verify && npm run knip"

effort M

Rollout order

  1. Docs only: fix paths in CLAUDE.md / AGENTS.md, make one the pointer. No code risk.
  2. Add the verify script. Use it in AGENTS.md. Repo stays green.
  3. Run npm run lint locally (not run in this audit). Record the count. Fix or turn off failing rules so it is green, then add it to CI for packages/*/src.
  4. Add zero-cost bans: no-restricted-imports for lucide-react, no-only-tests, ban-ts-comment (5 hits to fix).
  5. Add the import-boundary rule and the ../ ban (fix 50 files, mostly autofixable by search/replace).
  6. Adopt @nkzw/oxlint-config with failing rules set to off. Ask first: dependency change.
  7. Enable rules one by one, one commit each: no-explicit-any (ratchet), no-console, exhaustive-deps, type-aware async rules.
  8. Opt-in: restrict timers and new useEffect with the error messages above.
  9. Add the feature map. Add knip to CI.

Skipped checks and risks

  • Not run (needs approval): npm run lint, typecheck, test, knip, builds. Lint backlog size and verify run time are unknown.
  • Counts come from rg text scans. any and non-null patterns may include false positives (for example strings, test code). Type-aware findings (floating promises) are not measured.
  • Boundary hits in finding 6 were listed by import path only. Some may be import type and allowed.
  • The oxlint preset version, rule names and react/set-state-in-effect availability must be checked against the installed oxlint before adoption.
  • Risk: banning useEffect or instanceof repo-wide would produce hundreds of failures. Use a ratchet (override list that only shrinks).
  • Risk: .npmrc has engine-strict and save-exact; a new dev dependency must be pinned exactly.
  • Scope: JS/TS only. Native code in packages/ios and packages/android was not audited.
