# Product

## Users

Solo builders and indie makers who use writeme as their external brain: capturing notes, processing reading, managing tasks, and thinking alongside AI. They have it open all day. They know their tools deeply and have chosen to invest in this one. The primary workflow is writing, then finding, then linking. The AI is a collaborator, not a gimmick.

## Product Purpose

An AI-native markdown editor and knowledge tool that does not require giving up power to gain calm. writeme replaces a combination of Obsidian, Notion, and a terminal by folding them into one coherent surface. Success looks like a user who opens it first thing and closes it last, without ever feeling like they are fighting the interface.

## Brand Personality

Calm, structured, trustworthy. Comfortable to live in for hours. The tool disappears into the work. Warm and organized without being precious or cluttered.

## Anti-references

- **Dev tool brutalism**: monospace everything, no visual hierarchy, looks like a config file. writeme is for builders, not for signaling that you are a builder.
- **AI startup aesthetic**: gradient blobs, glassmorphism panels, purple-to-teal gradients, hero metrics, anything that screams "Series A pitch deck." writeme's AI is a background collaborator.
- **Minimal blog template**: too sparse, no density, feels like a theme rather than a tool. Users have serious information needs.

## Design Principles

1. **The interface earns its invisibility.** When the user is writing, UI chrome should recede. Sidebars, tabs, and toolbars exist to navigate, not to announce themselves. Default view breathes; power is a gesture away.
2. **Warmth through structure, not decoration.** Visual hierarchy built on space, weight, and rhythm. No decorative borders, shadows, or fills that exist only to break monotony. Calm comes from predictability.
3. **Complexity is earned, not displayed.** writeme has a terminal, diagram blocks, AI, and math. None of this should be visible until the user reaches for it. Progressive disclosure, always.
4. **Trust through consistency.** Same component vocabulary everywhere. If a button looks different in two places, one is wrong. Same hover state, same focus ring, same form-control shape across every screen.
5. **Density by user choice.** The tool supports multiple tabs, resizable panels, and a terminal. But the zero-state should feel open. Let users discover density; do not impose it.

## Accessibility & Inclusion

WCAG AAA target: 7:1 contrast ratio for text. 3:1 for UI components. A prefers-reduced-motion track is required for every animation in the product.
